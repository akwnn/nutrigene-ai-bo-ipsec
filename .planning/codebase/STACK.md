# Technology Stack

**Analysis Date:** 2026-08-24

## Languages

**Primary:**
- Python 3.11 (the recorded working environment is 3.11.15) - all library code in `src/boec/`, experiment drivers in `scripts/`, and validation in `tests/`.

**Secondary:**
- POSIX shell/zsh - orchestration and thread-pinning in `scripts/drive_p6.sh`; command examples throughout `docs/` assume a macOS shell.
- YAML - preregistered experiment and lab campaign configuration in `configs/experiment/e2.yaml`, `configs/experiment/e4.yaml`, and `configs/lab/coating_2026-08-06.yaml`.
- Markdown - the scientific record, preregistrations, methods, claims, audit trails, and paper-ready findings under `docs/`, `data/published/`, and `data/lab/overlay/`.
- JSON/CSV/Parquet - committed experiment results and data interchange under `results/`, `data/published/`, `data/lab/derived/`, and `data/oracles/`.

## Runtime

**Environment:**
- CPython >=3.11, concretely Python 3.11.15 for the pinned numerical environment documented in `requirements.txt`.
- CPU-only execution on macOS/arm64; `requirements.txt` explicitly records no GPU, Docker, Hydra, or Ax requirement.
- Keep numerical framework threads at one before importing NumPy/Torch. `src/boec/runner.py` pins `OMP_NUM_THREADS` and `MKL_NUM_THREADS`; many long-running scripts also pin `VECLIB_MAXIMUM_THREADS` and `OPENBLAS_NUM_THREADS`.
- Some sweep drivers use `concurrent.futures.ProcessPoolExecutor`, but each worker remains single-threaded; examples include `scripts/run_q52_budget_to_target.py`, `scripts/run_p6_families.py`, and `scripts/run_q59_hartmann_no_screen.py`.

**Package Manager:**
- `uv` is the documented environment/bootstrap tool: `uv venv --python 3.11`, `uv pip install -r requirements.txt`, then `uv pip install -e .` (`requirements.txt`). Standard `pip` is compatible with the same files.
- Dependencies are exact-pinned in `requirements.txt`; build metadata lives in `pyproject.toml`.
- Lockfile: missing. Reproducibility relies on exact direct/transitive pins in `requirements.txt`, committed artefacts, and recorded runtime provenance rather than a resolver lock.
- A local `.venv/` is present but is a developer environment, not a portable project artefact.

## Frameworks

- GPyTorch 1.15.2 - Gaussian-process models and likelihood machinery in `src/boec/surrogate.py`, `src/boec/spread_gp.py`, and related diagnostics.

**Testing:**
- pytest 9.1.1 - test runner configured in `pyproject.toml`; tests live in `tests/` and include unit, regression, scientific-invariant, provenance, and slow full-campaign gates.
- The `slow` marker is deliberately included in the default suite because it represents an E1 kill condition; explicitly use `pytest -m "not slow"` only for a shortened developer run (`pyproject.toml`).

**Build/Dev:**
- setuptools >=61 with the `src/` package layout - editable installation and build backend configured in `pyproject.toml`.
- PyYAML 6.0.3 - reads preregistered and lab configuration in `configs/`.
- Matplotlib 3.11.1 - publication/research figures generated by `src/boec/figures.py`, `scripts/make_final_spade_figures.py`, and related scripts into `results/figures/`.

- `numpy==2.4.6`, `scipy==1.17.1`, `pandas==3.0.5` - numerical and analytical substrate used by essentially every experiment and paper table.

- `statsmodels==0.14.6`, `patsy==1.0.2` - classical response-surface models and inferential analyses that form the comparison arm.

**Infrastructure:**
- `flowio==1.4.0` - FCS 2.0/3.0/3.1 event reader used by `src/boec/lab/fcs.py` for CytoFLEX/CytExpert acquisitions.

- Python standard-library `zipfile` and `xml.etree.ElementTree` parse XLSX and DOCX directly in `src/boec/lab/plate.py` and `src/boec/lab/protocol.py`; do not add OpenPyXL/python-docx unless a new requirement cannot be handled by the existing narrow parsers.

## Configuration

**Environment:**
- No application secrets or network credentials are required for normal analysis. No `.env` file is present at repository root.
- Install the package editable before running scripts: `python -m pip install -e .`. Pytest alone can import `boec` via `pythonpath = ["src"]`, but standalone scripts cannot (`pyproject.toml`).
- Set BLAS/OpenMP thread counts before framework imports for reproducible reductions. Follow `scripts/drive_p6.sh` or the setup in `src/boec/runner.py`.
- Run from the repository root because scripts use repo-relative paths such as `results/`, `data/oracles/`, and `configs/`.
- Prefer CPU `torch.double`; the numerical methods and committed artefacts are built around double precision and seeded CPU execution in modules such as `src/boec/campaign.py` and `src/boec/norms.py`.

**Build:**
- `pyproject.toml` defines package name `boec`, version `0.1.0`, Python floor, setuptools discovery, pytest paths, and the slow marker.
- `requirements.txt` is the authoritative runtime/test pin set and documents environment rationale.
- `configs/experiment/e2.yaml` and `configs/experiment/e4.yaml` are versioned preregistrations, not generic defaults. Preserve their version/history semantics when reproducing paper experiments.
- `configs/lab/coating_2026-08-06.yaml` defines the in-house coating campaign context; keep its 2-D FN/VTN box isolated from the Hall/Ogle six-protein coded space.

## Data and Artefact Formats

**Inputs:**
- Synthetic oracle ensembles: versioned Parquet plus JSON audit records under `data/oracles/<ensemble-version>/`; loaded through `src/boec/oracles.py`.
- Published dataset: canonical coded CSVs under `data/published/`, generated from source PNG/JSON and an independent CSV transcription using `scripts/digitize_hall_ogle.py` and `scripts/build_published_dataset.py`.
- Wet-lab raw data: FCS, CytExpert XIT/XML, Leica/EVOS JPEG plus Leica `.metadata`, Thermo XLSX, and protocol DOCX under `data/lab/raw/`.
- Human scientific decisions: role maps, campaign condition maps, checksum manifest, and gating record under `data/lab/overlay/`.

**Outputs:**
- Machine-readable experiment evidence is committed primarily as JSON in `results/`, commonly accompanied by `.log` files and generated PNG/HTML figures under `results/figures/`.
- Lab ingestion writes disposable CSV/JSON products to `data/lab/derived/`; `data/lab/derived/RUN.json` records the build and promotion status.
- Paper interpretation and claim strength live in `docs/METHODS.md`, `docs/RESULTS.md`, `docs/CLAIMS.md`, `docs/source_verification.md`, and related audit documents. Treat the machine artefact as the numeric source and the docs as the interpretation/provenance layer.

## Reproducibility Requirements

**Determinism:**
- Seed randomness per configuration, oracle instance, and campaign seed; the canonical seeding path begins in `src/boec/campaign.py` and is consumed by design, noise, and posterior-draw code.
- Keep the committed ensemble authoritative. `docs/METHODS.md` explains that regenerating from a seed alone is insufficient because numerical optimizer behaviour is not covered by the ensemble version hash.
- Preserve common-random-number and shared-initial-design rules where registered; experiment-specific fairness contracts live in `configs/experiment/e2.yaml` and tests such as `tests/test_runner.py` and `tests/test_campaign.py`.

**Provenance:**
- New long-running result writers should record git SHA, dirty state, argv/config, Python/package versions, timestamps, and thread settings. Concrete patterns exist in `scripts/run_p1_kernel_gate.py`, `scripts/run_p3_cells.py`, `scripts/run_q52_budget_to_target.py`, and `scripts/run_q59_hartmann_no_screen.py`.
- Preserve checkpoint/resume output rather than restarting completed cells; large sweep scripts append completed rows and atomically rewrite JSON, for example `scripts/run_q59_hartmann_no_screen.py`.
- Validate computed numbers against committed reference rows where a fidelity gate exists; `scripts/run_k1_replay_gate.py`, `scripts/probe_e2_determinism.py`, and `scripts/validate_final_spade_release.py` are canonical examples.
- Raw lab inputs are immutable and SHA-256 verified via `data/lab/overlay/MANIFEST.sha256` and `src/boec/lab/manifest.py`; derived outputs are disposable and reproducible.

## Platform Requirements

**Development:**
- macOS/arm64 with Python 3.11 is the verified platform; Linux CPU may work but is not the recorded numeric reference environment.
- Memory requirements vary sharply. Most tests are modest, while GP sweeps can require multiple CPU-hours and substantial RAM. Respect script-specific worker defaults; `scripts/run_q54_hill_spread_gp_draws.py` documents worker deaths near 900 MB RSS per worker.
- Git is a runtime provenance dependency for scripts that call `git rev-parse`/`git diff`; run from a clone with history intact.
- Execute `pytest` before relying on a new paper result; scientific gates are part of the default suite by design.

**Production:**
- Not applicable as a hosted application. The deliverable is a reproducible research repository: package code, committed data/results, audit logs, figures, and paper-support documents.
- No database server, message broker, web server, cloud runtime, GPU runtime, or container deployment is detected.
