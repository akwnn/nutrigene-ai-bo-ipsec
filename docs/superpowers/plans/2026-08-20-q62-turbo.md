# Q62 TuRBO-1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add TuRBO-1 so qLogNEI may only propose inside an adaptive trust region, with frozen BoTorch defaults, history kept on restart, and a runner that gates on stored qLogNEI means before any TuRBO row is trusted.

**Architecture:** Pure TR math lives in `boec.turbo`. `Campaign` optionally holds a `TurboState` and passes TR bounds into existing `propose()`. The runner compares `turbo1_qlognei` to stored qLogNEI / DoE / `doe_ascent` JSON; it does not overwrite E2 or Q56.

**Tech Stack:** Python 3.11, BoTorch 0.18, PyTorch, existing `Campaign` / `qLogNEI` / `reported_best_curve`.

## Global Constraints

- Ticket is **Q62**. Q60/Q61 remain confirmation-average and q=1 BO.
- Output `results/q62-turbo.json` only. Never overwrite E2, Q56, Q58.
- Frozen defaults: `length_init=0.8`, `length_min=0.5**7`, `length_max=1.6`, `success_tolerance=3`, `failure_tolerance=ceil(max(4/q, d/q))`.
- Noisy incumbent = argmax of GP posterior mean at **visited** wells, not max y.
- Restart keeps all `train_X` / `train_Y`. Do not retune on Hill.
- Acquisition inside TR stays qLogNEI. Opening is Sobol 2d+2.
- Do not add TuRBO-m, SAASBO, SCBO, MES.
